# westend61-statistics

Расширение для Chrome: собирает продажи из личного кабинета фотографа
[Westend61](https://www.westend61.de) и показывает, сколько принесли
каждая фотография, съёмка, месяц и партнёр. Сделано по образцу
cavan-statistics, на React по архитектуре
[bulletproof-react](https://github.com/alan2207/bulletproof-react).

## Установка

```bash
npm install
npm run build
```

1. Откройте `chrome://extensions` и включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение** и выберите папку `dist`.
3. После каждой новой сборки нажмите на карточке расширения кнопку ↻.

## Как пользоваться

1. Войдите в аккаунт фотографа на westend61.de в этом же Chrome.
2. Нажмите на значок расширения — откроется вкладка со статистикой.
3. Нажмите **Загрузить данные**. Сбор занимает меньше минуты: запросы идут
   по одному с паузой 1–2 секунды, чтобы не нагружать Westend61. Каждый раз
   скачивается всё заново — это всего несколько запросов.

Интерфейс на английском, кнопка **RU / EN** переключает язык; рядом — переключатель
светлой и тёмной темы. Внизу страницы кнопка **Удалить все данные** стирает из
браузера всё, что сохранило расширение.

Данные хранятся только в браузере (`chrome.storage.local`) и никуда не отправляются.

## Как это работает

Расширение загружает страницы кабинета в открытой вкладке westend61.de
(`chrome.scripting`, `world: "MAIN"`), поэтому запросы идут с вашей сессией —
так же, как запросы самого сайта. Все страницы запрашиваются на английском
(`lang=en`), чтобы разбирать даты и суммы.

| Страница / запрос                                 | Данные                                                  |
| ------------------------------------------------- | ------------------------------------------------------- |
| `/photographers/dashboard`                        | общий доход с фото, число фото онлайн, начало контракта |
| `/photographers/revenue/index` (My Earnings)      | все лицензии: ID фото, сумма, партнёр, дата             |
| ссылка «My portfolio» (поиск по фотографу)        | весь портфель: ID, описание, превью                     |
| `/photographers/dashboard/query?q=imagesOnline`   | сколько фото вышло онлайн в каждый день                 |
| ingestion.westend61.de `/ingestion/mySubmissions` | старые сабмишены: названия, статусы, ID принятых фото   |
| ingestionneo.westend61.de `/mySubmissions`        | новые сабмишены: то же самое                            |

My Earnings запрашивается сразу за весь период с года начала контракта,
по 100 лицензий на страницу. Сумма собранных продаж сверяется с общим доходом
на дашборде; при расхождении на странице появится предупреждение.

Westend61 не показывает дату загрузки каждого фото. ID фото (`EVKF00130`)
растут по мере выхода фото онлайн, поэтому дата оценивается так: n-е фото по
ID получает дату n-го фото из графика «My Images online». Если какие-то фото
сняты с продажи, даты немного сдвигаются.

Съёмки — это сабмишены из обеих систем Westend61 (старой и новой). На
странице сабмишена у каждого принятого фото указан его ID, по нему фото
связывается со съёмкой. Страница сабмишена загружается заново, только если
сабмишен новый или у него изменились статус или число принятых фото, так что
повторное обновление занимает несколько запросов. Для этих запросов
расширение открывает в фоне вкладки ingestion.westend61.de и
ingestionneo.westend61.de; нужно быть залогиненной и там. Если сабмишены не
загрузились, остаются съёмки с прошлого обновления и показывается предупреждение.

Фото, которых нет ни в одном сабмишене, попадают в строку «Без съёмки». Там их
можно отметить галочками и собрать в свою съёмку; ручная привязка важнее
сабмишена. Свои съёмки хранятся отдельно от данных Westend61, поэтому повторное
обновление их не сбрасывает.

## Публикация в Chrome Web Store

`npm run package` собирает расширение и кладёт архив для магазина в
`release/`. Тексты для страницы магазина, ответы для вкладки Privacy, политика
конфиденциальности, скриншоты, промо-картинка и пошаговый план публикации — в
папке `store/` (инструкция: `store/listing.md`).

`.gitignore`: там личные данные.

## Структура проекта

Проект следует структуре папок bulletproof-react:

```
src/
├── app/              # слой приложения — связывает всё воедино
│   ├── routes/       # компоненты маршрутов
│   ├── app.tsx       # корневой компонент (провайдеры + роутер)
│   ├── provider.tsx  # глобальные провайдеры (error boundary и т.п.)
│   └── router.tsx    # конфигурация роутера
├── assets/           # статические файлы (иконки, изображения, шрифты)
├── components/       # общие переиспользуемые компоненты
│   ├── ui/           # компоненты дизайн-системы (button, modal, …)
│   ├── layouts/      # компоненты-раскладки
│   └── errors/       # error boundary / фолбэки
├── features/         # модули-фичи (самодостаточные)
├── hooks/            # общие хуки
├── lib/              # преднастроенные библиотеки (например, API-клиент)
├── stores/           # глобальные хранилища состояния
├── styles/           # глобальные стили и Sass-переменные
├── types/            # общие типы TypeScript
└── utils/            # общие утилиты
```

Модуль-фича (`src/features/<feature>/`) самодостаточен и может содержать
собственные `api/`, `components/`, `hooks/`, `stores/`, `types/` и `utils/`.

## Правила архитектуры

Кодовая база **однонаправленная** — импорты могут идти только в одну сторону:

```
общие слои  →  features  →  app
```

- **Общие** слои (`components`, `hooks`, `lib`, `stores`, `types`, `utils`)
  не могут импортировать из `features` и `app`.
- **Features** не могут импортировать из `app` и не должны обращаться к другим
  фичам — композиция фич выполняется в слое `app`.

Эти правила **enforce'ятся ESLint** (`no-restricted-imports` в `eslint.config.js`);
их нарушение проваливает линтинг. Для абсолютных импортов из `src/` используйте
алиас `@/` (например, `import { Button } from '@/components/ui/button'`), а внутри
одной фичи — относительные импорты.
